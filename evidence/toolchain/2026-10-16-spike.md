## Limitations and residual tooling debt

- API 24 is the configuration floor, not a runtime-support claim. API 24 emulator evidence remains required.
- The first clean Gradle build per daemon emitted an SDK XML warning from resolved `com.android.tools:repository:32.1.0`, whose parser supports XML through version 3 while version 4 metadata was present. It persisted after command-line-tools 23.0 alignment and did not affect analysis, tests, or either APK. DevOps will reassess it on the next Flutter or Android Gradle Plugin upgrade.
- Removing the application-owned NDK declaration passed both APK builds. Flutter still contains native runtime libraries and its build tooling selects an internal native baseline; this does not establish an application dependency on custom native code.
- No emulator, device, camera, scanner, accessibility, security-runtime, clean-host, or distribution behavior was tested. Those were outside the spike.
- A warm local dependency cache does not establish fully offline or cross-machine reproducibility.
- Xcode and CocoaPods findings are irrelevant because iOS is excluded.
